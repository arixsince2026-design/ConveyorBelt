# AI Diagnostic Agent — Implementation Plan

## Goal
An "AI Diagnose" experience for belts that behaves like an investigating agent: it walks through investigation steps (gather sensor trends → check thresholds → review alert history → inspect maintenance records → correlate), shows findings per step, and produces a root-cause report with risk drivers and recommended actions. It runs **fully deterministic today (no API key needed)**, with an optional Edge Function hook that adds LLM-written narrative once a key is configured.

## Design decisions
- **Diagnosis engine runs client-side** (`src/lib/diagnosis.ts`) using existing data access + the prediction engine (`src/lib/predictions.ts`) and thresholds (`src/lib/alertRules.ts`) we already built. RLS applies naturally, no service-role key needed, works offline of any LLM.
- **LLM stays optional and server-side**: `supabase/functions/ai-diagnose` receives the computed facts and returns an LLM narrative only when `LLM_BASE_URL` + `LLM_API_KEY` secrets are set (OpenAI-compatible). If the function isn't deployed or errors, the UI silently falls back to the deterministic report.
- Agent-style presentation: stepped investigation with findings revealed per step (short staged progress), then the final structured report.

## Work items

1. **`src/lib/diagnosis.ts` — diagnostic engine**
   - `diagnoseBelt(belt, history, alerts, maintenanceLogs, thresholds)` returning:
     - `steps`: ordered investigation steps, each with status, a human-readable finding (e.g., "Vibration averaged 6.8 mm/s over 14 days — above the 5 mm/s warning threshold", "Last maintenance 92 days ago", "3 prior alerts on this belt, 2 resolved after corrective maintenance").
     - `report`: root-cause analysis (most-weighted degraded metrics + trend from `predictBeltRisk`), risk score/label, days-to-failure, recommended actions (rules per driver type), and a plain-language summary.
2. **`src/components/AiDiagnosisDialog.tsx`**
   - Dialog opened per belt; runs steps sequentially (animated, ~400ms per step), shows findings, then renders the final report (badges for risk, drivers list, recommendations, summary).
   - "Download report" button (txt via Blob). Copy-to-clipboard too.
   - If configured, fetches LLM narrative from the Edge Function and appends an "AI Narrative" section; gracefully skips on any failure.
3. **Wire-in points**
   - Dashboard: add an optional `onDiagnose` action to `BeltStatusCard` (sparkles button) and render the dialog in `Dashboard.tsx`.
   - Belts page: "Diagnose" action per row.
4. **`supabase/functions/ai-diagnose/index.ts`** (optional enhancement)
   - Deno Edge Function: CORS, POST `{ facts }` → calls OpenAI-compatible `LLM_BASE_URL/chat/completions` with a system prompt to write an executive diagnostic narrative from the supplied facts; returns `{ narrative }`. Returns a clear "not configured" response when secrets are absent. Header comments document setup (`supabase secrets set LLM_BASE_URL=... LLM_API_KEY=...`, `supabase functions deploy ai-diagnose`).
5. **Verification**
   - `npx tsc --noEmit`, `eslint src` (no new errors), `npm run build`.
   - Manual run: dev server already running at http://localhost:8080 — verify the dialog flow end-to-end in the browser on the Belts page (deterministic path, no key).

## Out of scope (future)
